## B. Shortlist with fairness slider — done 2026-09-20

- `lib/use-tube-graph.ts`: `totalWeight(sum, n, budget)` and `blend(p, maxMins, sumMins, n, budget, λ) = p · fairnessWeight^(1−λ) · totalWeight^λ`. At λ = 0 this is bit-identical to `p * fairnessWeight(...)` (`x ** 1 === x`, `x ** 0 === 1`), so the ranking, `liveTop`, the demo script and the probes are unchanged. **Deviation from the plan:** `totalWeight` uses sharpness 6, not the plan's 0.7. At 0.7 the weight spanned 0.69–0.80 over the shortlist while Jev's probabilities differed 2×, so the far end of the dial reordered nothing in 3/3 samples; at 3 it reordered 2/3, at 6 3/3 and the λ = 1 order reads as "by total" among places that fit (see the comment on `TOTAL_SHARPNESS`).
- `lib/meet-shortlist.ts` (new, pure): `buildShortlist` = top 3 of the blended `probabilities` (same order `liveTop` reduces over, so row 1 = what Enter picks), each with `mins[]` through `personTime` (A1: TfL's minutes on the committed pick once landed, graph estimate otherwise, `est` flag), `spread`, `total`, raw `p`, and `why[]`: `best match` (max raw p), `fairest` (min spread), `fastest total` (min total); one origin → `closest` instead of the two time axes. A tie on an axis goes to the higher-p row. A row that wins nothing is `runner-up`, or `best overall` when it heads the list.
- `app/meet/shortlist.tsx` (new): header "Shortlist" + "prioritising equal times / balancing both / prioritising fastest total"; range input "most equal ↔ fastest total" (hidden with one origin); rows `TOP · name`, mono `a / b / c · N apart · est.`, why line. Hover / focus → `onPreview(id)`; click → `onCommit(id)` = the existing `commit(id)`, so TfL verification, veto and re-pick are untouched. Touch: first tap previews, second commits (`pointerType` recorded on pointerdown). The committed pick's row is highlighted in `--good`, the previewed one in `--accent`.
- `app/meet/client.tsx`: state `lambda` (default 0, not in the URL) and `previewed`; `probabilities` memo uses `blend`; `shortlist` memo; `preview` is derived (null once its row leaves the list, no effect); `previewRoutes` = `graph.pathBetween(o, preview)` per origin; `shown = hovered ?? preview` feeds the map's `hovered` / `hoverLabel`, so the previewed station gets the same minutes label as a map hover. Rendered above the card in the same bottom-right container (now `flex-col gap-2`); hidden when `!lit`, no origins, `nobody`, **and in the `demo=1` recording layout** (full-width it covered most of the 4:5 map and the script never touches the dial — flip `!big` in the JSX to include it). `VERIFY_SLACK_MIN`, `REPICK_DELAY_MIN`, the veto and re-pick effects, `SCRIPTS` and `lineThatMatters` are untouched.
- `app/meet/map.tsx`: props `previewRoutes` (graph paths, stroke 3 at 60 %, a 150 ms fade, no dash reveal, `pointer-events: none`) and `shortlist` (hollow accent rings r 7 on ids that are neither `top` nor `pick`).
